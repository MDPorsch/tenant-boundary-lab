## WHY THIS FLAW IS DIFFERENT

The other four flaws change the *status code* (a 200 where a 403 belongs). This one does not: the
response is byte-for-byte the denial a correct app returns, and `test_tl17_the_flawed_answer_is_
indistinguishable_from_the_patched_one` proves it. Only the database shows the write happened, which
is exactly the case where a status-only runner reports a clean result. The exploit principal is gina
(owner of the **suspended** tenant C): a suspended tenant is refused whatever else is broken, so with
every other flaw on, a changed row still points at this flaw alone.
