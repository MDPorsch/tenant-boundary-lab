## HOW THE TESTS WERE VALIDATED (beyond "they fail")

A failing test only proves the test cannot run. To check the red tests are *satisfiable and
sensitive*, a throwaway reference spike (about 110 lines, written in the agent's scratch directory,
**not committed**, because the work order forbids routes before policy approval) implemented the M1
interface, and the tests were mutation-tested against it:

* Unmutated spike: **96 / 96 pass**. (All numbers below were re-run against the final committed tests.)
* 27 injected security bugs (trusted `X-User`/`X-Role`/`X-Tenant-Id`, skipped principal/membership/
  tenant-state/capability gates, existence oracle via 403, audit poisoning, pre-auth audit write,
  write-before-deny, cached membership, body parsed before auth, echoed request id, signature/exp/nbf/
  iat/aud/iss/required-claims verification disabled, lifetime cap removed or off by one): **27 / 27 killed**.
* Findings fixed because of this: the "expired token" variant also violated the 900 s lifetime cap, so a
  verifier that never checked `exp` would still pass (mutation `exp_not_verified` survived until fixed);
  two of my own mutants were invalid or equivalent and were not counted (a no-op mutation, and an
  `alg` change that PyJWT already refuses).
* Same technique on the docs: 5 deliberate corruptions of the Markdown tables were all caught by
  `test_docs_sync.py`. Loader tests initially passed for the wrong reason (a mutation hit a comment; a
  rename hit only the first of two tables) and were tightened to assert the specific error.

The spike and mutation scripts are not in the repository, so these numbers are not independently
reproducible from it. Say the word and I will recreate them.
