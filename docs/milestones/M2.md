## HOW IT WAS BUILT, AND WHAT WENT WRONG

**Red first.** The contract and decisions were committed before any test, and 356 tests before any
handler (commit `4a37a0f`). Against the M1 code 300 failed and 56 passed (the M1 gates already
covered those). The failures were grouped by message: every one was the `501` placeholder or a
missing field of it, none was an import, fixture or test-code error.

**A blemish in the history.** The first M2 commit (`a3f6956`, docs only) already contains the updated
test matrix, one commit before the catalog it is checked against (`4a37a0f`), so the docs-sync test
fails at that single commit. Every other commit is green, except `4a37a0f`, which is red by design
(300 failed, 56 passed). The final tree is green.

**First run against the real handlers.** Every failure was on the test side; none was a handler
bug. In total seven tests failed before I fixed them, and I fixed the tests, not the code:

* one **M1** test (the "no GET writes an audit row" control) encoded M1's reality: a private-contact
  read IS audited (D-10, D-37), so I changed it to allow exactly that one row;
* two **M1** registry tests asserted that only `/me` is implemented; they now expect every route to
  be implemented, and the 501 mechanism has its own test;
* four parametrizations of my own key-echo check searched the whole response for the word `id` or
  `status` (both appear in every problem body); it is now structural (the key must not appear in
  `errors`).

A first-run pass proves little, which is why the next two paragraphs exist.

**What the new tests could not see.** The handlers pre-check, so an HTTP test cannot tell "the write
statement refused" from "the pre-check refused first". The claim of this milestone is that the
statement refuses by itself, so I tested it in two ways that the pre-check cannot mask: each
statement called directly with the state changed underneath it (39 tests), and a wrapper that
changes the database between the handler's pre-check and its write (21 tests: revocation,
downgrade, suspension, disabled principal, market removal, a stale version, the quota taken by
another writer, the last owner revoked, and a race that never settles, which is 503).

**Mutation testing.** The M1 tool, re-run on the M2 tree, first reported 67 killed and **2 "not
applied"** (exit 2): M2 had restructured the code two M1 mutants targeted (the `/me` return statement
and the now-async endpoint), so their patches no longer matched. A stale mutant must not count as a
pass, so I updated both to the new code and re-ran the whole tool: 69 of 69. For M2, 49 injected bugs: 48 caught on the first run. The survivor was
`nan_accepted`: with the parser's NaN refusal removed, a NaN was still rejected, but only as a wrong
*type*, so the guard was invisible. D-30 says NaN is not JSON, so I pinned the error code
(`invalid_json`) rather than delete the guard. Before the run I also reasoned through the mutants and
closed four gaps I expected to survive: gate 7 evaluated before body validation, a cross-tenant
project update aimed at the statement, a non-canonical cursor encoding, and an anonymous chunked
body (401, never read). That was my analysis, not the tool's finding.

**Mistakes of mine, caught by the tooling:** the file-writing tool turned two `\u` escapes into
literal bidirectional-control characters inside a test file and a source file (ruff's
Trojan-Source rule flagged both; the source now builds the set from code points); several
positional-argument and long-line lint findings; a wrong keyword call in one test.

**Coverage found real untested paths:** the "object vanished after the gates" branches, a non-ASCII
cursor, duplicate error de-duplication and two `None` returns. All are now covered, including the
fail-closed 503 for a committed write whose read-back fails.

## DECISIONS NEEDING YOUR APPROVAL

Full text in `DECISIONS.md`.

* **D-31** a market that does not exist gets the same `403 authz.market_denied` as one the tenant may
  not use, and gate 7 is evaluated before body validation.
* **D-32** the project quota (1 000 per tenant) counts hidden-market projects too.
* **D-34** `PUT /members/{principal}` updates existing memberships only; it can re-activate a revoked
  one; stale `version` is 409; the last-owner rule is decided inside the statement.
* **D-37** successful `project.create`, `project.write`, `member.role.write` and
  `contact.private.read` write an `allow` row in the same transaction; a failed audit write rolls the
  change back.
* **D-38** a write that keeps losing a race is retried at most 3 times with the gates re-run each
  time, then answers 503 with no audit row.

Informational: D-30 body rules, D-33 unsigned cursor, D-35 atomic re-check, D-36 bounds, D-39 audit
`resource_type`.
