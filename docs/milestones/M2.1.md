## 2. What was wrong with the timing test

I measured before changing anything. On this machine, in process, interleaved, 300 samples per class:

| Finding | Before |
|---|---|
| SQL statements per request, hidden market / foreign tenant / revoked member / missing | **5 / 4 / 4 / 3** (each failed gate returned early) |
| Hidden vs missing, median latency | **+23.5%**, p = 0.0002 |
| Foreign vs missing | **+10.7%**, p = 0.0005 |
| First half vs second half of one run (drift) | **+28.6%**, larger than the signal |

The old test tolerated a factor of five, so it **passed while a real, repeatable 24% difference
existed**; and because it sampled all of one class and then all of the other, drift alone could
produce differences of that size in either direction.

## 3. What changed

**Tests (committed red first, `ad00fde`):** a deterministic test that every not-visible outcome of a
route family runs the identical SQL sequence (no clock involved); an interleaved, randomised
permutation test with a 15% effect floor that must trigger in **both** of two independent rounds; a
check that the detector can see a real difference; and unit tests of the statistics themselves
(including a false-alarm rate check). Five structural tests and the statistical test failed on the
old code, for the reasons above.

**Code (D-40):** gates 3-5 now run the same lookups in the same order for every outcome, with a nil
id standing in for anything that does not exist, and only then decide in the documented order.

| After | |
|---|---|
| SQL statements, all four outcomes | **5 / 5 / 5 / 5** |
| Hidden vs missing | **+0.9%** (0.015 ms) |
| Foreign vs missing | **+0.7%** |
| Drift, first vs second half | **+0.3%** |

## 4. Mistakes of mine on the way

* My structural test first compared the plain and the nested invoice routes in one family; they
  legitimately differ (the nested query has an extra predicate). Fixed by comparing outcomes within
  one route.
* My "can the detector see anything" check compared a 200 with a 404. That stopped being a real
  difference once a 404 cost about as much as a 200, which is the point of D-40. It now compares a
  100-row page with the context probe.
* Five M1 mutants went stale because the gate code they patch changed. The tool reported them as
  not applied (exit 2) instead of passing them; I retargeted them and added three mutants that
  reintroduce an early return.

## 6. What this does and does not claim (LIMITATIONS L-07, L-24)

It claims: identical SQL for every not-visible outcome, and no repeatable timing difference of 15% or
more in process. It does **not** claim constant time: about 1% (0.015 ms) is still statistically
detectable at 300 samples. A real network, TLS, a loaded server and PostgreSQL are untested.
